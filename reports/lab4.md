# 问答作业

## 第六章：
+ root inode 作用如下：
    
    1. 文件系统的逻辑起点​​

        root inode是文件系统的根目录（/）的元数据入口，记录了根目录的​​数据块位置​​、​​大小​​、​​权限​​等信息。所有文件和子目录的访问均从根目录开始逐级解析

    2. ​目录结构的组织基础​
        通过root inode，系统可以定位根目录下的直接子项（如文件或其他目录的 inode），从而递归构建完整的目录树

    3. ​​元数据与数据的桥梁​​
        root inode通过指针（直接/间接块）关联到存储根目录内容的数据块，这些数据块中保存了根目录下各文件的名称及其对应的 inode 编号

+ root inode 损坏的后果

    1. ​目录树断裂​

        若root inode的元数据（如数据块指针、文件类型标记）损坏，系统无法找到根目录的实际内容，导致​​整个文件系统无法遍历​​，表现为挂载失败或显示为空目录
    
    2. 数据访问完全失效​​

        所有文件和子目录的路径解析依赖根目录的完整性。若root inode损坏，用户无法通过路径访问任何文件，即使数据块本身未损坏

    3. 潜在的元数据连锁损坏

        若root inode的错误写入导致其指向无效或冲突的数据块，可能进一步破坏其他 inode 或数据块，加剧文件系统崩溃风险

## 第七章：
1. 示例：通过管道统计文件行数
   
   在 Linux 终端中，可以通过管道（|）将 cat 和 wc 命令组合，快速统计文件的行数：

   ```bash
   cat filename.txt | wc -l
   ```

   原本 `cat filename.txt​​` 命令会将文件内容输出到标准输出（stdout）而​​通过管道 `|`​​：将 cat 的输出重定向到 `wc` 的标准输入（stdin）使得后续​​`wc -l`​​ 命令能够从标准输入读取数据并统计行数

2. 改进方案：命名管道（FIFO）
    
    + 核心思想：通过在文件系统中创建具名管道，多个进程可以通过打开同一个管道文件进行通信
    + 实现方式：使用 mkfifo 创建命名管道文件，多个进程通过打开同一个管道文件进行读写
    
    优点：管道通过名字标识，多个进程可方便共享，无需为每对进程单独建匿名管道
